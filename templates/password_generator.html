Why a strong, random password matters

Most account breaches don't come from someone guessing a password character by character — they come from reused passwords. When one site gets breached and your email/password combo leaks, attackers try that same pair everywhere else. A unique, random password per account means one leak doesn't cascade into a dozen compromised accounts.

Length matters more than complexity tricks. A 20-character password with just letters and numbers is harder to brute-force than an 8-character password stuffed with symbols. That's why this tool defaults to 16 characters and lets you go up to 128 — longer is generally better, as long as you're not manually memorizing it (that's what a password manager is for).

Tips

  • Use a different password for every account — a password manager (Bitwarden, 1Password, etc.) makes this practical.
  • Prefer length over cleverness. correct-horse-battery-staple-style passphrases are memorable and long, but for anything stored in a password manager, a fully random string like the ones this tool generates is stronger.
  • Enable two-factor authentication wherever it's offered — it protects you even if a password does leak.
  • Avoid predictable substitutions (P@ssw0rd) — attackers' wordlists already account for these.

FAQ

Is this actually secure, or just for show? The password is generated using the browser's crypto.getRandomValues() (Web Crypto API) when you use the page directly, or Python's secrets module when you call the API — both are cryptographically secure random number generators, not the predictable Math.random()/random module.

Do you store the passwords I generate? No. Nothing is logged, saved, or transmitted anywhere beyond generating the result for you. See our Privacy Policy.
